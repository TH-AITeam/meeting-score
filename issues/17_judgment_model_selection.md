# #17 [decision] 判断モデル(ローカル LLM)選定

**Labels**: `decision`, `model`, `P0`
**Milestone**: v0.5

## 概要

ローカル推論(#11)・SFT(#13)・DPO(#14) で使う **判断 LLM** を比較して決める。後段のすべてが依存するため、#11 着手より前に結論を出す。

## 評価対象

候補は実装時に最新の OSS 日本語対応モデルから 3〜5 個ピックアップする。**この Issue ではあらかじめ特定モデルを固定しない**。

候補選定の入口:
- 日本語の汎用ベンチ(JMT-Bench, Nejumi など)上位
- A100 80GB に収まる規模(おおむね 7B〜14B)
- 商用利用可能なライセンス
- vLLM/sglang など主要推論サーバ対応

## 評価軸

| 軸 | 計測方法 | 重み |
|---|---|---|
| 日本語評価精度 | サンプル会議3本 + ゴールデンで Spearman / ペアワイズ accuracy | **最重要** |
| JSON 出力安定性 | 100発言で `_RESPONSE_SCHEMA` を `guided_json` で強制した時の成功率・分散 | 高 |
| 推論速度 | 1発言あたりの p50 / p95 レイテンシ | 中 |
| メモリ占有 | bf16 / 4-bit でのGPU使用量 | 中 |
| 学習しやすさ | QLoRA 設定の参考実装の充実度、tokenizer の癖 | 中 |
| ライセンス | 商用可、再配布可、蒸留可 | 中 |

## やること

- [ ] 候補リスト(3〜5モデル)を `docs/model_candidates.md` にまとめる
  - 各モデルの公開時期、パラメータ数、コンテキスト長、ライセンス、得意領域
- [ ] **ゼロショット比較**: 各候補に既存プロンプトをそのまま叩いて、`evals/` で metric を取る
- [ ] **JSON 安定性測定**: `evals/stability.py`(#4) で各モデルの分散を比較
- [ ] **コスト測定**: 1会議(30分相当=約100発言)の推論時間
- [ ] **総合スコアシート**を `docs/model_selection_v1.md` に作る
- [ ] **第一採用 + 控え**を1つずつ決める
- [ ] 決定理由を Decision Record として残す(ADR形式)

## 完了条件

- 候補比較結果が一表にまとまる
- 第一採用モデルが決まり、`config.yaml.example` に記載される
- 後続 Issue (#11, #13, #14, #16) が「採用モデル」を参照する形で実装に入れる

## 注意

- ゼロショット精度だけで決めない。**SFT 後の伸びしろ**も重要(7B より 14B の方がゼロショット良くても、QLoRA 後は逆転することもある)
- 採用したモデルは v0.5 以降固定にせず、半年〜1年ごとに見直す(`docs/model_history.md` で世代管理)
- 評価用の検証データ(`evals/datasets/v1/`)は **固定**。比較中に変えない
